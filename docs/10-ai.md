# Phase 06 — a natural-language instruction becomes a validated configuration

`onward-generator ai plan` turns an instruction such as

> Generate a historic urban area with four-storey buildings, detailed facades, interiors in only two buildings, and maximum priority on Quest performance.

into validated copies of the three configurations the existing stages read: project, heights, and detail. The model never writes a configuration directly. Decision: `docs/decisions/ADR-006-ai-intent.md`.

Placement gestures and texture choice are separate. See ADR-010 and ADR-009.

## Flow

1. **Provider** (`ai/providers.py`). Returns text and where it came from. It does not interpret the text.
   - `ollama`: local Ollama. Loopback only. Any other host is refused, and system proxies are ignored.
   - `none`: no model. A person writes the intent (`--intent FILE`).
   - `replay`: reuse the reply stored from an earlier run.
2. **Parser** (`ai/intent.py`). Strict JSON: no prose, no code fences, no duplicate keys, no NaN. Validated against `config/intent.schema.json`, at most 64 KiB. Nothing in the text is executed or evaluated.
3. **Planner** (`ai/planner.py`). Deterministic code translates the intent into changes on copies of the base configurations. A whitelist rejects any other difference.
4. **Output.** Relative paths are rewritten and everything is validated again. Files are written only when there are no errors and, when required, after confirmation.

## The intent

| Field | Values | Written to | Effect |
| --- | --- | --- | --- |
| `facade_detail` | `low`, `medium`, `high`, `null` | project `/quality/detail_level` | Recorded only. No stage reads it today |
| `residential_levels` | integer or `null`. Valid 3–5 with the default heights config | heights `/typical_levels/residential_multi` | Geometry of residential buildings that have no observed height or storeys |
| `interior_buildings` | integer 0–50, or `null` | detail `/interiors/max_buildings` and `/interiors/enabled`, and `/interiors/min_buildings` when the new ceiling is above 0 and below it; project `/generation/interiors` (recorded only). The stage then draws one count from `min_buildings` up to that maximum, within `max_triangles`. The default ceiling is 8 and the floor is 5 | Geometry |
| `performance_priority` | `max`, `balanced`, `null` | no configuration | Whether a cost increase is an error or a warning |

`unsupported_requests` lists what the model could not translate, with reason `protected_field`, `not_supported`, or `ambiguous`. `summary` is a sentence from the model, stored as unverified text.

`residential_levels` allows 1–50 in the schema, but the height estimator clamps a type estimate to `fallback_m.residential_multi` (9–15 m at 3 m storeys). A value outside 3–5 would be ignored silently, so it is an error (`levels_outside_allowed_range`). The range is computed from the heights configuration.

## What the model cannot change

1. **It cannot say it.** The intent schema has `additionalProperties: false` and has no fields for the area, coordinates, sources, performance limits, or export. A reply with those fields is refused (`intent_additionalProperties`).
2. **Whitelist.** After translation, `guard` diffs each configuration against its base and refuses any difference outside:
   - project: `/quality/detail_level`, `/generation/interiors`;
   - heights: `/typical_levels/residential_multi`;
   - detail: `/interiors/max_buildings`, `/interiors/min_buildings`, `/interiors/enabled`.

   The resolved area (centre, boundary file, and margin) must be the same (`protected_change`).
3. **Warnings on the instruction.** Deterministic patterns notice mentions of coordinates, sources, export, and performance limits (`instruction_mentions_protected`), and of style, period, lighting, or weather (`instruction_mentions_unsupported`). They run even when the model omits the phrase.

Requests the model marks `protected_field` or `not_supported` become warnings and are not applied.

## Performance limits

The reference is the default configuration. The phase 05 measurement on the Quest predates the interior defaults of the ADR-004 amendment, so those are not yet measured on the headset. A geometry change that raises cost (more storeys, more interiors, turning interiors on):

- with `performance_priority: max`, is an **error** (`exceeds_measured_configuration`);
- with `balanced` or `null`, is a **warning** (`not_measured_on_device`). Measure again as in `docs/09-perf.md`.

The budgets in `detail.default.json` and the project's optimisation block cannot be edited by the intent.

## Confirmation

A plan **needs confirmation** when it changes geometry or has any warning. Without `--confirm`, no configuration is written: `proposal.json` is written and the command exits `3`. To apply exactly the reviewed plan, without calling the model again:

```bash
onward-generator ai plan --provider replay --replay out/proposal.json --confirm --out out
```

A plan with no errors, no geometry change, and no warnings is written directly. `facade_detail` alone is that case: it is recorded and has no effect.

## Outputs

| File | When |
| --- | --- |
| `project.json`, `heights.json`, `detail.json` | A valid plan that was confirmed, or that did not need confirmation. Pass them with `--config` |
| `intent.json` | The validated intent |
| `ai_run.json` | The log of a run that wrote files |
| `proposal.json` | A plan waiting for confirmation |
| `rejected.json` | A refusal. No configuration is written |

The log (`onward_generator.ai_run` 0.1.0) stores the date, the generator version, the instruction and its SHA-256, the provider (host, model, digest, server version, quantisation, options, `eval_count`, duration), the system prompt and its hash, the intent-schema hash, the base configuration hashes, the raw reply and its hash, `intent_origin` (`ai_generated` or `user_supplied`), the unverified summary, the intent, the changes, the diagnostics, `confirmed`, `status`, and the output hashes.

Replay refuses a reply that does not match its hash, or bases or a schema that have changed (`replay_base_changed`, `replay_schema_changed`). Files are not overwritten without `--overwrite`, and the file being replayed is never overwritten.

## Providers and privacy

- Ollama must be `127.0.0.1`, `localhost` (pinned to 127.0.0.1), or `::1`. Any other host is refused before connecting.
- No model is downloaded. If the model is missing, the error lists the installed models.
- The default model is `qwen3:14b`. `--model`, `--seed`, and `--timeout-s` are configurable.
- The model receives the instruction, the system prompt, and the schema. It does not receive geographic data or project files.

## Street profile (plan D2)

A second, separate contract, off by default: `map.json` `"street_profile": true` (`run --street-profile`). The intent above is not widened ([ADR-006](decisions/ADR-006-ai-intent.md) and [ADR-010](decisions/ADR-010-overgrow-ai-plan.md) amendments of 8 November 2026, proposed until a headset session). Code: `src/onward_generator/ai/street_profile.py`.

Before `run` plans its stages, the loopback Ollama model receives the brief, the map centre and how many library props each props profile would keep. It never receives the library ids, the scene or a file. It answers one object of [street_profile.schema.json](../config/street_profile.schema.json) 0.1.0: one id per field, from a closed list. `map_default` keeps what the map already does. An optional `summary` (at most 200 characters) is stored as unverified text; no code reads it, and it never reaches a command line.

| Field | Ids | Setting (pointer) | Stage flag | Cites |
| --- | --- | --- | --- | --- |
| `dominant_typology` | `mediterranean`, `central_european`, `anglo`, `latin_american`, `haussmann`, `generic` | `/materials/facade_style` | `materials apply --facade-style <id>` | ADR-020, ADR-027 |
| `palette` | `extended_pools` | `/materials/repetition` | `materials apply --repetition --cell-m <combine_cell_m>` | ADR-009 (C1) |
| `props_profile` | `intact` (intact), `worn` (worn, damaged), `wrecked` (damaged, wrecked, burned) | `/overgrow/selection` | `overgrow place --selection config/street_profile_selection.json` | ADR-010 |
| `abandonment` | `years_10`, `years_30`, `years_100` | `/overgrow/profile_years` | `overgrow place --profile 10 \| 30 \| 100` | ADR-010 |
| `cover` | `off` (0), `light` (8), `full` (24) | `/cover/max_props` | `perf cover --max-props 0 \| 8 \| 24` | ADR-032 (C7) |

- `dominant_typology` picks only the map-wide trim atlas style. It never reclassifies a building: the per-building typology of ADR-024 is unchanged, and an observed OSM or Catastro colour, era or typology always wins. A style without an atlas (without `regional_facades`) stays on the per-material path, as `--facade-style` always did.
- A user setting wins and the id is recorded as `skipped` with reason `user_setting`: a named `map.json` `facades.style`, `"repetition": true`, or a `config/prop_selection.json`. `palette` is also skipped (`texture_plan_not_calm`) when the map's texture plan would fail the calm check `--repetition` makes, so the profile never makes `materials` fail. A props group with no library row is skipped (`props_profile_empty`). `cover` acts only when `sightline_cover` is already on (`profile_inactive` otherwise); the profile can never switch the cover stage on.
- **Guard.** The translation runs over an effective-settings document that also holds `/area`, `/center`, `/sources`, `/export`, `/budgets`, `/core`, `/buildings_sha256` (the OSM extract) and `/sightline_cover`. Any difference outside the five pointers above is refused (`AI_PROFILE_PROTECTED`): the neutral profile is used and the reason recorded, as in `planner.guard`.
- **Retry and fallback.** At most two calls; the second quotes the first rejection. Then the neutral profile (every field `map_default`, provenance `estimated`) with the reason. A provider error, a closed port or a missing Ollama never fails the run.
- **Replay.** `config/street_profile.json` (`onward_generator.street_profile_record` 0.1.0) keeps `origin` (`ai_generated`, `replay` or `rules`), `provenance`, `attempts`, `reason`, `diagnostics`, the `raw` reply and `raw_sha256`, `schema_sha256`, `prompt_sha256` (system prompt, prompt version and instruction), `inputs_sha256` (brief, centre to 1e-5, style ids, library ids with their condition, `sightline_cover`), the `ids`, the unverified `summary`, the provider provenance and one `changes` row per id that is not `map_default`: `field`, `id`, `pointer`, `stage`, `flag`, `before`, `after`, `status` (`applied` or `skipped`), `reason`, `effect`, `adr`, `origin`. A record whose hashes all match and whose origin is `ai_generated` or `replay` is replayed without a call; a rules record is never replayed. A stale reply is moved to `street_profile.<raw_sha256[:12]>.json` first, and an archive is never overwritten.
- **Stages read only the record.** `next:` lines and `run` add the flags of the `applied` rows, each a literal of the table, plus `--street-profile config/street_profile.json`. Each stage checks the record again (every id in its enum, every change the effect of its id) and adds a `street_profile` block (`schema_version`, `raw_sha256`, `ids`, `provenance`) to `materials_report.json`, `overgrow_report.json` or `cover_report.json`. The block is the same for a reply and its replay, so a replayed run writes the same files. A missing or tampered record gives no flags and a warning; the model is never called from a stage.
- **Off.** With no key, or `false`, nothing is read or written and every command and output is as before.

## Diagnostic codes

| Code | Severity | Meaning |
| --- | --- | --- |
| `empty_response`, `response_too_large`, `invalid_json`, `invalid_root` | error | The reply is not a strict JSON object |
| `intent_required` | error | A required field is missing |
| `intent_additionalProperties` | error | An unknown or protected field |
| `intent_type`, `intent_enum`, `intent_minimum`, `intent_maximum`, `intent_const`, `intent_maxLength`, … | error | A value outside the schema |
| `levels_outside_allowed_range` | error | Storeys the estimator would clamp |
| `exceeds_measured_configuration` | error | A cost increase with priority `max` |
| `protected_change` | error | A difference outside the whitelist, or a different area |
| `provider_error` | error | Ollama did not answer, returned HTTP, or the model is missing |
| `replay_base_changed`, `replay_schema_changed` | error | The replay is no longer faithful |
| `not_measured_on_device` | warning | A cost increase that has not been measured on the headset |
| `protected_request_ignored`, `unsupported_request` | warning | What the model did not apply |
| `instruction_mentions_protected`, `instruction_mentions_unsupported` | warning | Detected in the instruction by rules |
| `recorded_only`, `no_parameters` | info | Recorded with no effect, or nothing to translate |
| `AI_PROFILE_SIZE` | error | Street profile: the reply is over 4096 bytes |
| `AI_PROFILE_JSON` | error | Street profile: the reply is empty or not strict JSON (trailing text, a code fence, NaN, a duplicate key) |
| `AI_PROFILE_SCHEMA` | error | Street profile: not an object, an unknown field, a missing field, or an id outside its list |
| `AI_PROFILE_PROVIDER` | error | Street profile: Ollama did not answer; the run goes on with the neutral profile |
| `AI_PROFILE_PROTECTED` | error | Street profile: a difference outside the five allowed settings, or a stored change that is not the effect of its id |
| `AI_PROFILE_RECORD` | error | Street profile: a stage was given a record that is missing, too large, or not a valid 0.1.0 record |
| `AI_PROFILE_STALE` | info | Street profile: the stored reply was made for other inputs; it was archived and the model asked again |
| `user_setting`, `texture_plan_not_calm`, `props_profile_empty`, `profile_inactive` | info | Street profile: why an id was recorded as skipped |

## Examples

```bash
onward-generator ai plan --instruction "Five-storey buildings, no interiors" --out out/ai
onward-generator ai plan --provider none --intent my_intent.json --out out/ai --confirm
onward-generator heights --scene geo_scene.json --config out/ai/heights.json --out out/heights
```

## Limits

- The model can invent values. Bounds, the whitelist, and confirmation limit the damage. They do not replace reading the proposal.
- The instruction warnings are heuristics, in Spanish and English. They can false-positive, and they can miss a new phrasing.
- `facade_detail` and the project's `generation.interiors` are recorded and have no effect. No stage reads them.
- The same model, digest, seed, and `temperature` 0 reproduced on the machine where it was tested. That is not a guarantee across Ollama versions or hardware. Confirmation uses `replay`, not a new call.
- `num_ctx` is sized from the prompt: its bytes divided by 3, plus 4096 tokens for the reply, rounded up to a multiple of 4096, at least 8192 and at most 32768. Ollama's default context (2048 to 4096 tokens) silently drops the start of a longer prompt, and the overgrow library alone is about 11k tokens. A prompt that needs more than 32768 is refused before the call. Provenance records `num_ctx` and `prompt_eval_count`.
- The intent covers four parameters. It does not propose variants or enrich attributes.
