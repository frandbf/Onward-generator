# Command reference

Every command is `onward-generator <command>`, the same as `python -m onward_generator <command>`. In Docker it is `tools/docker/run.sh onward-generator <command>`. `version` prints `0.1.0`. The order the stages run in, and each one's inputs and outputs, are in [01-pipeline.md](01-pipeline.md).

| Command | What it does | Exit |
| --- | --- | --- |
| `version` | Print the generator version. | `0` |
| `platform` | Print the host (`macos` or `linux`), where it came from, and the Unity, adb, log, and Asset Store cache paths. `--json` for machine output. The global `--platform` goes before any command. | `0`, `2` for an unknown platform |
| `doctor` | Read-only check of Python and the pinned versions, GEOS, PROJ, and EPSG:25830 offline, the configuration schema, free disk, and the host platform, and the export toolchain (Unity 2021.3.23f1, adb, and the SDK package). A missing toolchain file is a warning. An unknown platform fails `host:platform`. | `0` ok, `1` if something fails |
| `validate-config` | Strict read, JSON Schema, and semantic rules. Each finding names the field, cause, and code. See `02-configuration.md`. | `0` valid, `1` invalid |
| `run` | Create a map and run every Python stage through `export package`, then Unity, then an optional Quest upload. See the README, *Try it* and *Make it yours*, and [01-pipeline.md](01-pipeline.md#1-map-folder). | `0` / `1` |
| `map create` / `map show` | One folder per map: name, latitude, longitude, radius, and area of interest. The id and `maps/<id>` come from the name. `create` downloads that square's `.osm` and writes `config/texture_plan.json`. `--textures` on an existing map rewrites only that plan. `show` prints the `geo` command for the folder. | `0` / `1` |
| `osm download` | Repeat the Overpass request for one map folder. | `0` / `1` |
| `geo` | Geographic pipeline. The command is in [docs/01-pipeline.md](01-pipeline.md#recipe-for-a-new-map). | `0` / `1` |
| `heights` | Building heights from `geo_scene.json`: `--scene`, `--out`, `[--config]`, `[--overrides]`, `[--secondary-overrides]`, `[--overwrite]`. See `04-heights.md`. | `0` / `1` |
| `overture fetch` | **Uses the network.** Overture places and buildings for the map bbox, from the STAC `latest` release or `--release`, reading only the files the release STAC index says meet the map, to `overture_*.parquet` with `.source.json` sidecars (default `data/raw/`): `--map`, `[--out]`, `[--release]`, `[--overwrite]`. The `overture` source plugin; `run --no-source overture` skips it. ADR-021. | `0` / `1` |
| `overture match` | Offline. Overture heights as `heights_overrides.overture.json`, places as `overture_places.json`, and a report: `--scene`, `--map`, `--out`, `[--config]`, `[--overwrite]`. ADR-021. | `0` / `1` |
| `cadastre download` | **Uses the network.** Catastro WFS requests (`BuildingPart`) for the scene bbox, in tiles of at most 1 km², in the CRS of the map's Catastro zone: `--scene`, `--out`, `[--margin-m]`, `[--overwrite]`. Spain without Navarre and the Basque Country. See `05-cadastre.md`. | `0` / `1` |
| `source list` | Registered source plugins (ADR-018): rank in `config/sources.json`, what each writes, its licence and whether the allowlist accepts it; with `--lat` and `--lon`, whether it covers that point. `[--config]` before `list`. Offline. | `0` / `1` |
| `source fetch` | **Uses the network.** A raster plugin's tiles for the box around the scene's buildings (plus 20 m) into `<out>/tile_NNN.bin` and `<out>.source.json`: `<id>`, `--scene`, `--out`, `[--overwrite]`. Refuses a plugin whose licence is not on the allowlist, and `es.catastro` (use `cadastre download`). See `04-heights.md#lidar-heights`. | `0` / `1` |
| `source normalize` | `heights_overrides.<id>.json` and `<id>_report.json` from a fetched raster: the median height inside each footprint shrunk by an inner buffer: `<id>`, `--scene`, `--raw`, `--out`, `[--overwrite]`. Offline. | `0` / `1` |
| `source merge` | One `heights_overrides.json` and a `sources_report.json` from several plugins' overrides, ranked by `config/sources.json` `priority`: `--overrides <id>=<file>` (repeat), `--out`, `[--overwrite]`. Offline. `run` adds it as the `overrides` stage when two or more plugins write overrides. | `0` / `1` |
| `cadastre match` | Catastro storeys to `heights_overrides.catastro.json` and a report: `--scene`, `--gml`, `--out`, `[--min-coverage]`, `[--overwrite]`. See `05-cadastre.md`. | `0` / `1` |
| `cadastre split` | Splits OSM footprints into one sub-building per Catastro construction and writes a new `geo_scene.json`, the overrides and the report: `--scene`, `--gml`, `--out`, `[--min-coverage]`, `[--split-min-coverage]`, `[--min-piece-area-m2]`, `[--min-piece-width-m]`, `[--overwrite]`. Offline. ADR-016. | `0` / `1` |
| `generate` | Base meshes: `--scene`, `--heights`, `--out`, `[--config]`, `[--no-preview]`, `[--overwrite]`. See `06-generation.md`. | `0` when the 03 → 04 check passes, `1` on a critical error |
| `detail` | Facade, roof and interior detail on a validated base: `--scene`, `--heights`, `--base`, `--out`, `[--config]`, `[--generation-config]`, `[--typology-config]`, `[--places]`, `[--overture-tints]`, `[--lidar-roofs REPORT]` (plan C3: flat or pitched roofs from a LiDAR plugin's `<id>_report.json` for this scene; `run` passes it with `map.json` `"lidar_roofs": true`), `[--no-preview]`, `[--overwrite]`. See `07-detail.md`. | `0` when the automatic checks pass, `1` on a critical error |
| `dress classify` | Recommend catalogue materials (Ollama, rules, or replay) for a sample. Does not modify the scene. `--apply` is refused. See `08-dress.md`. | `0` valid report, `1` rejection or provider failure |
| `dress style` | Copy the detail scene: 16-sided trees, benches, and an atlas. Does not rebuild facades. See `08-dress.md`. | `0` / `1` |
| `asset-store scan` / `asset-store import` | Local catalogues from **your own** downloaded Unity Asset Store packs ([ADR-035](decisions/ADR-035-local-asset-store-catalogues.md)). Run on the host (it needs the Unity editor and its cache), not in Docker: `.venv/bin/onward-generator asset-store scan`, then `asset-store import [--only ID…] [--max-mb 400] [--max-triangles 8000] [--refresh] [--unity PATH] [--cache PATH]`. Writes `assets/asset_store_<id>/`, which git ignores. `ONWARD_LOCAL_CATALOGUES=0` hides them from a run. | `0`; `1` when every chosen package failed; `2` no Unity editor or host |
| `props catalog` | Validate the Asset Store catalogue and, with `--inventory`, bind imported prefabs. | `0` / `1` |
| `props place` | Copy a scene and write instances that have OSM evidence (surface parking). Does not put cars on the carriageway. Does not bake FBX into the GLB. | `0` / `1` |
| `materials apply` | Copy a `dress` or `detail` scene and remap atlas tiles from that map's `config/texture_plan.json`. `--download` is the only network step, and it is for an older Poly Haven plan. A library plan reads files already in `config/dress/imported_library.json`. `--no-tile-cache` bakes every photo tile again instead of reading the tile cache (`08-dress.md`). `--facades trim|legacy` (default `trim`) and `--facade-style NAME|auto` (default `auto`) choose the trim-sheet facade atlas or one material per facade part ([ADR-020](decisions/ADR-020-trim-sheet-facades.md)). See `01-pipeline.md`. | `0` / `1` |
| `panoramax apply` | Under development. With `map.json` `"panoramax": true`, project 360° street photos onto exposed facades and write `scene_panoramax`. Off, it writes nothing. Collision is copied byte for byte. Photos stay CC BY-SA 4.0. `"panoramax_atlas": true` (off by default) packs the crops into one image per combine cell, tints the photographed trim walls to the nearest strip and reports coverage. See `01-pipeline.md`. | `0` / `1` |
| `signs place` | Copy the dressed scene and hang one plate, with the OSM `name`, on the facade at a junction. A street with no name gets no plate. Also draws the shop signs and window vinyls recorded by `detail`. Collision is unchanged. | `0` / `1` |
| `overgrow place` | Copy the scene and add grass, vines, trees, wrecks, and the props in `--library`. `--profile` is 10, 30, or 100. `--seed` defaults to 48152. `--zone-radius` or `--zone-polygon` is in local metres. With no zone, the default is a 110 m block. The drive lane and the building footprints stay. `overgrow fit` then rejects a prop that is the wrong size or in the wrong place. | `0` / `1` |
| `overgrow library` / `fetch` / `fetch-sketchfab` | List the installed props and the Sketchfab licence review, download the named CC0 Poly Haven models, or download Sketchfab models the review already marked usable (needs `SKETCHFAB_API_TOKEN`). | `0` / `1` |
| `bounds` | Copy a dressed scene and add a playable perimeter wall. Does not rewrite the `generate` output. | `0` / `1` |
| `perf measure` / `layout` / `device` / `drawcalls` | `measure` counts GLB contents offline. `layout` writes the measurement fixture; `--playable` writes gameplay layout 0.3.0 (Free Roam, Uplink, Assault, Escort, Hunt, Evac, Retrieval). `device` and `drawcalls` read headset logs. See `09-perf.md`. | `0` / `1` |
| `export package` / `verify` | Write an export package for the Unity adapter (`--project` with `export.enabled`, `--detail`, `--layout`, `--out`, `[--config]`). Never overwrites. The build and the headset copy are `tools/unity/onward_adapter/run_export.sh`. See `12-export.md`. | `0` / `1` |
| `ai plan` | Instruction to a validated configuration. `--instruction` or `--instruction-file`. `--provider ollama` (local, `--model`, default `qwen3:14b`), `none` (no model, `--intent FILE`), or `replay` (`--replay FILE`). `--out`, `[--confirm]`, `[--overwrite]`. See `10-ai.md`. | `0` written, `1` rejected, `3` needs confirmation |

`run --source <id>` and `run --no-source <id>` (repeatable) turn a source plugin on or off for the map and store the choice in `map.json` `sources`; `--catastro` and `--no-catastro` are aliases for `es.catastro`. An unknown id, or one given to both, is a usage error. Usage errors return `2`. `run --verbose` prints each stage's full output; `run --preview` also draws the diagnostic PNGs of `generate` and `detail`; `run --no-unity` stops after `export` and prints the `task unity` command for the host.

## Benchmark

`task bench` runs `python tools/bench/bench.py` in the image, with the host's `uname -srm` and, on macOS, its GPU as `--host-os` and `--host-gpu`. It is measurement tooling, not a pipeline stage and not a quality gate. See [01-pipeline.md](01-pipeline.md#benchmark).

| Command | What it does | Exit |
| --- | --- | --- |
| `task bench` / `task bench -- run [--only ID...] [--offline] [--against REPORT] [--lidar-roofs] [--lightmap-pages-max N]` | Generate the four reference maps (`bench_murcia`, `bench_madrid`, `bench_paris`, `bench_krakow`) with seed 48152 in a new `output/bench/runs/<UTC stamp>/` folder, through every Python stage up to `export package`. Write `bench_report.json` and `contact_sheet.png`, then compare with the previous run, or with `--against`, in `bench_diff.md`. The first run uses the network. `--offline` refuses to start while a frozen download is missing. `--lidar-roofs` switches the plan C3 roofs from the nDSM spread on in each run copy only and adds `lidar_roofs` (`flat`, `pitched`, `unclassified`, `classified_pct` of core buildings) to each map of the report. `--lightmap-pages-max N` (plan C5) sets `build.lightmap_pages_max: N` in each run copy's export card only, so `export package` lowers the lightmap density until the estimate fits N pages. Never runs Unity, never reads or writes `maps/` | `0` / `1`, `2` usage |
| `task bench -- report RUN_DIR` | Read the packages of a finished run again. Unity seconds appear once `task unity` has built a bench package | `0` / `1` |
| `task bench -- compare OLD NEW` | Write `bench_diff.md` beside NEW and print it: old, new and delta for each map and metric | `0` / `1` |
| `task bench -- check A B` | Exit `1` and name the JSON paths when two reports differ outside `timings` | `0` same / `1` |
